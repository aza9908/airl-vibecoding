# Публикация продукта в интернете

Читается навыком `airl-start` на последнем шаге. Публикация — всегда по явному
согласию человека, не раньше.

## Как предложить

Покажи выбор прямо в переписке:

```
Продукт работает у вас на компьютере. Хотите, чтобы он открывался по ссылке
из интернета?

A) Да, самый простой способ — рекомендую
B) Да, но нужен свой домен и база данных
C) Пока нет, оставим локально

Рекомендую A: занимает пять минут, бесплатно, ссылку сразу можно отправить
коллегам. Домен и базу можно добавить потом, ничего не переделывая.
```

Ответ «нет» — спокойно закругляйся, скажи, что вернуться к этому можно в любой момент
командой `/airl-start`.

## Вариант A — Netlify

Подходит для сайтов и веб-приложений без своего сервера. Бесплатно, ссылка вида
`имя-проекта.netlify.app`.

**Что делаешь ты:**

1. Проверь, что проект собирается: выполни команду сборки и убедись, что появилась
   папка с готовыми файлами.
2. Установи инструмент публикации и опубликуй:

   ```bash
   npm install -g netlify-cli
   netlify deploy --prod
   ```

3. При первом запуске откроется браузер для входа. Скажи человеку об этом заранее,
   иначе он растеряется.
4. Инструмент спросит, какую папку публиковать — укажи ту, куда собирается проект.

**Что говоришь человеку после:**

```
Готово. Продукт открывается по ссылке: [адрес]

Что дальше можно сделать в личном кабинете Netlify:
- привязать свой домен вместо адреса на netlify.app;
- включить автоматическое обновление сайта при изменении кода.

Обновить сайт после правок: выполнить netlify deploy --prod ещё раз.
```

## Вариант B — Firebase

Подходит, когда нужны база данных, вход по логину и хранение файлов в одном месте.
Бесплатный уровень щедрый, но при росте начнёт тарифицироваться — скажи об этом прямо.

**Что делаешь ты:**

1. Установи и войди:

   ```bash
   npm install -g firebase-tools
   firebase login
   ```

2. Свяжи папку с проектом Firebase:

   ```bash
   firebase init hosting
   ```

   На вопросы отвечай, сверяясь с `ARCHITECTURE.md`: какая папка со сборкой, нужен ли
   режим одностраничного приложения.

3. Опубликуй:

   ```bash
   firebase deploy
   ```

**Обязательно предупреди до начала:**

```
Firebase считает деньги по факту использования. Пока пользователей мало,
всё бесплатно, но лимит расходов лучше поставить сразу, а не после первого счёта.

Это делается один раз, руками: Firebase Console → ваш проект → Usage and billing →
Budgets & alerts → задать месячный потолок.

Сделайте это до того, как отправите ссылку коллегам.
```

## Общие правила

- Ключи доступа никогда не попадают в опубликованный код. Перед публикацией убедись,
  что `/airl-security` пройден и критических находок не осталось.
- Публикация в интернет означает, что продукт увидит любой человек со ссылкой.
  Скажи это вслух до, а не после.
- После публикации **проверь наблюдаемо**: открой адрес, пройди главное действие
  из `DESIGN.md`, убедись, что оно работает. «Команда отработала без ошибок» —
  не доказательство.
- Что-то сломалось на живом адресе — сначала откат к прошлой версии, потом разбор.
