# Firebase

Закрывает и сайт, и данные одной пачкой. Самый короткий путь для большинства проектов.

## Предупреди человека до начала

```
Firebase — сервис Google. Нужен обычный аккаунт Google, отдельно ничего
покупать не надо.

Сейчас откроется браузер и попросит войти — это ваш шаг, я за вас войти не могу.

Сайт и база бесплатны, пока пользователей мало. Если продукту понадобится
серверная часть, Google попросит привязать карту — предупрежу отдельно,
когда до этого дойдёт.
```

## Что нужно от человека

- аккаунт Google
- проект в консоли Firebase (`console.firebase.google.com` → Add project)
- **номер проекта** (Project ID) — точная строка из настроек, не название

## Установка и вход

```bash
npm install -g firebase-tools
firebase login
```

Откроется браузер — дождись, пока человек подтвердит, не иди дальше сам.

## Настройка

```bash
firebase init hosting
```

На вопросы отвечай, сверяясь с проектом:

- **public directory** — папка со сборкой, **не `public`**. Для Vite это `dist`,
  для Create React App — `build`. Оставить подсказанное по умолчанию — самая частая
  ошибка, в интернет уедет пустая страница.
- **Configure as a single-page app** — **да** для сайтов на Vue и React. Иначе
  прямая ссылка на внутреннюю страницу вернёт ошибку 404.
- **Set up automatic builds with GitHub** — нет, это отдельный разговор.

Проверь получившийся `firebase.json`: папка должна быть настоящая, и для
одностраничных сайтов должно быть правило перенаправления на `index.html`.

## Ключи

Сайт — это набор файлов, которые скачивает браузер. Значит **всё, что попало в
сборку, видно любому посетителю**. Ключ Firebase для сайта публичен по задумке,
это нормально и не утечка. А вот ключ платёжной системы или админский доступ туда
класть нельзя никогда — их место в настройках сервиса, а не в коде.

## Публикация

```bash
npm run build
firebase deploy --only hosting
```

Адрес получится вида `номер-проекта.web.app`.

## Защита данных — обязательный шаг

Если продукт хранит данные в Firebase, новый проект по умолчанию **открыт на чтение
и запись всему интернету**, а через 30 дней закрывается целиком. Оба состояния плохие.

Правила должны быть написаны до публикации. Минимум — данные человека доступны
только ему:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId}/{document=**} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
  }
}
```

```bash
firebase deploy --only firestore:rules
```

Проверь, что нигде не осталось `allow read, write: if true` — это открытая дверь.

## Свой домен

Консоль Firebase → Hosting → Add custom domain. Firebase выдаст записи, которые
нужно прописать у регистратора домена. Для домена в зоне .kz, купленного на ps.kz, —
в личном кабинете ps.kz.

Скажи человеку: адрес заработает не мгновенно, обновление может занять до суток.
Это нормально, чинить нечего.

## Если что-то сломалось

```bash
firebase hosting:rollback
```

Возвращает предыдущую версию сайта. Сначала откат, потом разбор — не наоборот.

## Деньги

Сайт: бесплатно в пределах 10 ГБ хранения и 360 МБ трафика в сутки — учебному и
раннему продукту хватает с большим запасом. База: бесплатно до 50 тысяч чтений в день.

Серверные функции требуют привязки карты. Если проект до них дошёл — скажи прямо:

```
Для серверной части Google просит привязать карту. Пока пользователей нет,
счёт будет нулевым, но потолок расходов лучше поставить сразу.

Firebase Console → ваш проект → Usage and billing → Budgets & alerts →
задать месячный лимит.

Сделайте это до того, как отправите ссылку коллегам.
```
