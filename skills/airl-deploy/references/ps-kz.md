# ps.kz

Казахстанский хостинг. Выбирают по одной из трёх причин: данные должны оставаться
в Казахстане, домен в зоне .kz уже куплен там, или компания за хостинг уже платит.

**Сначала выясни, что именно у человека.** Обычный хостинг и сервер — это два разных
мира, и перепутать их значит потерять час впустую.

| | Обычный хостинг | Сервер (VPS) |
| --- | --- | --- |
| Управление | панель Plesk в браузере | командная строка |
| Можно запускать программы | **нет** | да, любые |
| Подходит для | готовых файлов сайта, PHP, WordPress | чего угодно |
| Продукт на Next.js с сервером, NestJS, свой API | **не заработает** | заработает |

Если у человека обычный хостинг, а продукту нужен сервер — скажи прямо и предложи
выбор: докупить VPS или разместить сайт на Firebase, оставив на ps.kz только домен.
Второе обычно дешевле и быстрее.

---

## Вариант A — обычный хостинг (панель Plesk)

Что нужно от человека: доступ в панель Plesk и данные FTP (адрес, логин, пароль).

### Что делаешь ты

1. Собери продукт: `npm run build`. Получится папка `dist` или `build`.
2. Проверь, что сайт не привязан к корню жёстко — если он ляжет в подпапку,
   в настройках сборки нужен правильный базовый путь.
3. Залей **содержимое** папки сборки (не саму папку) в `httpdocs` домена.

Пароль в командной строке остаётся в истории. Либо положи его в `~/.netrc` с правами
600, либо — что честнее для неопытного человека — предложи залить файлы через
файловый менеджер прямо в панели Plesk, это две минуты мышкой.

4. **Обязательно** положи рядом файл `.htaccess`, иначе внутренние страницы будут
   отдавать ошибку 404:

```apache
<IfModule mod_rewrite.c>
  RewriteEngine On
  RewriteBase /
  RewriteCond %{REQUEST_FILENAME} !-f
  RewriteCond %{REQUEST_FILENAME} !-d
  RewriteRule . /index.html [L]
</IfModule>
```

5. **Защищённое соединение.** В Plesk: домен → SSL/TLS Certificates → Install a free
   basic certificate. Там же включи переход с `http` на `https`.

### Что сказать человеку

```
Готово, продукт открывается по адресу: [ссылка]

Чего на этом тарифе нет: возврата к прошлой версии одной кнопкой. Если после
обновления что-то сломается, придётся заливать файлы заново — поэтому папку
со сборкой я сохраню.

Обновить сайт после правок: соберу заново и залью те же файлы.
```

## Вариант B — сервер (VPS)

Что нужно от человека: IP-адрес сервера и пароль root. При первичной настройке
провайдер кладёт все доступы в файл `/root/passwords.txt` на самом сервере — если
человек их не нашёл, они там.

### Сначала безопасность, потом всё остальное

```bash
ssh root@IP_СЕРВЕРА
```

Первое подключение спросит про отпечаток ключа — это нормально, подтверди.

Заведи отдельного пользователя и закрой вход под root:

```bash
adduser deploy && usermod -aG sudo deploy
mkdir -p /home/deploy/.ssh && cp ~/.ssh/authorized_keys /home/deploy/.ssh/
chown -R deploy:deploy /home/deploy/.ssh && chmod 700 /home/deploy/.ssh
```

В `/etc/ssh/sshd_config`: `PermitRootLogin no`, `PasswordAuthentication no`, затем
`systemctl restart ssh`.

**Не закрывай текущее подключение, пока не проверил вход новым пользователем из
другого окна.** Иначе можно запереть себя снаружи, и открывать будет техподдержка.

Закрой лишние двери:

```bash
ufw allow OpenSSH && ufw allow 80 && ufw allow 443 && ufw enable
```

На младших тарифах памяти немного, и провайдер сам создаёт файл подкачки на 512 МБ.
Для сборки продукта этого может не хватить — **собирай на компьютере человека, а на
сервер клади готовое**.

### Размещение готовых файлов

```bash
rsync -avz --delete dist/ deploy@IP:/var/www/проект/
```

Настройка nginx, файл `/etc/nginx/sites-available/проект`:

```nginx
server {
    listen 80;
    server_name домен.kz www.домен.kz;
    root /var/www/проект;
    index index.html;
    location / { try_files $uri $uri/ /index.html; }
}
```

```bash
ln -s /etc/nginx/sites-available/проект /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
```

`nginx -t` перед перезагрузкой обязателен: битая настройка уронит все сайты на сервере.

### Размещение продукта с сервером

Программу держит systemd, снаружи её показывает nginx:

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection 'upgrade';
    proxy_set_header Host $host;
}
```

Ключи и пароли — в отдельном файле, который читает systemd (`EnvironmentFile=`),
права 600, владелец `deploy`. В проект такой файл не сохраняется.

### Защищённое соединение

```bash
apt install certbot python3-certbot-nginx
certbot --nginx -d домен.kz -d www.домен.kz
```

Сертификат выпустится и будет продлеваться сам. Условие одно: домен уже должен
указывать на IP сервера, иначе выпуск не пройдёт.

## Домен

Домен, купленный на ps.kz, настраивается в личном кабинете:

- **хостинг или сервер на ps.kz** — запись типа A на IP сервера
- **сайт на Firebase, домен на ps.kz** — записи, которые выдаст консоль Firebase

Скажи человеку: изменения расходятся по интернету до суток. Не объявляй поломку
в первые полчаса — сначала проверь `dig домен.kz`.

## Деньги

Обычный хостинг стартует примерно от 384 ₸ в месяц, сервер дороже и зависит от тарифа.
**Уточни актуальную цену на ps.kz перед тем, как называть её человеку** — тарифы меняются,
а он будет принимать решение по твоей цифре.

Отдельно посчитай продление домена: первый год часто дешевле последующих.
