# Supabase

Хранит данные: таблицы, вход по логину, файлы. Настоящая база с таблицами и связями —
то, что нужно, когда данные сложнее списка записей.

## Скажи это человеку сразу

```
Важная деталь: Supabase хранит данные, но сам сайт не размещает. Адрес,
по которому продукт откроется, всё равно нужен отдельно — сделаем на Firebase
(или на вашем сервере ps.kz, если выбрали его).

Это не лишний шаг и не переплата: Supabase бесплатен на старте, размещение
сайта тоже.
```

Дальше публикуй сам сайт по `firebase.md` или `ps-kz.md`, а здесь — только данные.

## Что нужно от человека

- проект на `supabase.com` (вход через GitHub — самый быстрый путь)
- номер проекта (Project Reference ID) из адресной строки панели
- пароль от базы, заданный при создании. Его показывают **один раз**. Потерян —
  сбрасывается в Settings → Database, ничего страшного.

## Два ключа, и путать их опасно

- **anon / publishable** — уходит в сайт, его видит любой посетитель. Так задумано.
- **service_role / secret** — открывает всю базу целиком, обходя любые ограничения.
  В сайт не попадает **никогда**. Утёк — вся база доступна на чтение и запись.

Перед публикацией проверь: в коде сайта строки `service_role` быть не должно.

## Защита данных — обязательный шаг

Новая таблица по умолчанию **доступна всем, у кого есть первый ключ**, а он лежит
в сайте у каждого посетителя. Без защиты база публична. Это самая частая и самая
дорогая ошибка на Supabase — не пропускай этот раздел.

Для каждой таблицы:

```sql
alter table public.записи enable row level security;

create policy "владелец читает своё"
  on public.записи for select
  using (auth.uid() = user_id);

create policy "владелец пишет своё"
  on public.записи for insert
  with check (auth.uid() = user_id);
```

Панель Supabase подсвечивает незащищённые таблицы предупреждением. Пройди по списку
и убедись, что предупреждений не осталось. Человеку скажи результат словами:
`Проверил: все таблицы закрыты, чужие данные посторонний прочитать не сможет.`

## Установка и связь с проектом

```bash
npm install -g supabase
supabase login
supabase link --project-ref НОМЕР_ПРОЕКТА
```

## Таблицы

Структура базы живёт в проекте файлами, а не кликами в панели — иначе продукт
невозможно будет поднять заново.

```bash
supabase migration new add_notes_table
supabase db push
```

**`supabase db push` меняет рабочую базу.** До запуска покажи человеку простыми
словами, что именно изменится, и дождись согласия.

**`supabase db reset` на рабочем проекте удаляет все данные.** Сам, без прямой
просьбы, эту команду не запускай никогда.

## Подключение к сайту

```js
import { createClient } from '@supabase/supabase-js'

const supabase = createClient(
  import.meta.env.VITE_SUPABASE_URL,
  import.meta.env.VITE_SUPABASE_ANON_KEY
)
```

Эти значения попадут в сборку сайта — так и должно быть. Данные защищает раздел
выше, и больше ничто.

## Частая поломка после публикации

Вход работал на компьютере и перестал работать на живом адресе — почти всегда дело в
этом: адрес сайта не добавлен в Authentication → URL Configuration → Site URL и
Redirect URLs. Проверяй это первым.

## Копия данных

На бесплатном тарифе автоматических копий нет. Перед изменением таблиц снимай копию:

```bash
supabase db dump -f backup.sql
```

Файл в проект не сохраняй — там настоящие данные людей.

## Деньги

Бесплатно: 500 МБ базы, 1 ГБ файлов, 50 тысяч активных пользователей в месяц.
Раннему продукту хватает.

Одна ловушка, о которой надо предупредить:

```
На бесплатном тарифе проект засыпает после недели без обращений — база
перестаёт отвечать, пока её не разбудить в панели.

Если продукт показывают раз в месяц, за день до показа стоит его открыть
и проверить, что всё живо.
```
