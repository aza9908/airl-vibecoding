# Шаг 2 — Архитектура: на чём собрать и сборка первой версии

## 📚 Покажи это человеку перед первым вопросом

```
🏗 Шаг 2 из 3 — Архитектура

Дизайн сказал, что строим и как это выглядит. Сейчас решим, на чём это
собрать и сколько будет стоить в месяц, а потом соберём первую рабочую версию.

Сначала 6 вопросов. Потом покажу выбор технологий с ценой — вы его утвердите.
Потом начнём собирать по частям: после каждой части остановимся, и вы своими
глазами посмотрите, что получилось.

Так ошибка находится через двадцать минут, а не через четыре часа, когда уже
непонятно, где она появилась.
```

## Перед стартом

Прочитай `DESIGN.md`. Его нет — скажи, что сначала нужен шаг `/airl-design`, и предложи
запустить. Человек настаивает — задай вопросы про продукт сам, но предупреди: без карты
экранов результат будет приблизительным.

## Главное правило

**Ничего не решай молча.** Выбрал технологию — объясни одной фразой, почему именно она
и сколько стоит. Не знаешь ответа — спроси.

## Режим существующего проекта

Код уже есть — сначала определи по файлам, на чём он собран, и покажи:

```
Разобрался, на чём собран проект:

**Основа**: [что нашёл]
**Данные**: [где хранятся]
**Вход по логину**: [есть или нет]
**Размещение**: [где живёт]

Работаем на этом же — переписывать с нуля незачем.

Что делаем?
A) Добавить новую возможность — расскажите какую
B) Починить то, что работает неправильно
C) Перенести на другое размещение
D) Свой вариант
```

Не предлагай сменить стек без веской причины и не спрашивай заново то, что видно
из кода. Скажи об этом прямо: «Вижу, что база уже есть, вопрос про хранение пропускаю».

## Как задавать вопросы

Один вопрос за сообщение, 3–4 варианта, один помечен рекомендуемым, одна строка почему:

```
**Вопрос 3 из 6 · Где будут храниться данные?**

A) Готовое облачное хранилище, бесплатно до тысячи пользователей — рекомендую
B) Своя база на своём сервере
C) Хранить ничего не нужно
D) Свой вариант

Рекомендую A: для первой версии хватает с запасом, настраивается за час,
платить начнёте только при реальном росте.
```

Ответ «не знаю» — бери рекомендацию, скажи об этом и иди дальше.

## Шесть вопросов

**1. Сколько человек будет пользоваться в первые полгода?**
До ста · до тысячи · больше тысячи. Определяет почти всё остальное, поэтому первый.
Подталкивай к честной оценке: завышенная цифра делает продукт дороже без пользы.

**2. Какие данные храним?**
Ничего · обычные (имена, заявки, тексты) · персональные и платёжные. Третий вариант
меняет требования к безопасности — скажи это сразу.

**3. Нужен ли вход по логину?**
Не нужен · для сотрудников · для клиентов · для тех и других.

**4. Нужна ли оплата внутри продукта?**
Не нужна · нужна, но позже · нужна сразу. «Позже» — хороший ответ: оплата удваивает
срок первой версии, и это стоит сказать вслух.

**5. Сколько готовы платить в месяц?**
Ноль · до 20 000 ₸ · до 100 000 ₸ · без потолка. Скажи честно: у большинства первых
версий всё помещается в ноль.

**6. Что уже есть и оплачено?**
Ничего · домен · хостинг или сервер · аккаунты сервисов. Уже оплаченное всегда
выигрывает у более удобного, но платного.

## Выбор технологий

### Лестница

Снизу вверх, без перепрыгивания:

1. то, что **уже есть и оплачено**;
2. **постоянно бесплатное** — бесплатный уровень без ограничения по сроку;
3. **дешёвое**;
4. **платное** — только когда первые три не закрывают задачу.

При бюджете «ноль» платное в рекомендацию не попадает вовсе. Человек назвал конкретный
инструмент как обязательный — альтернативы ему не предлагаются.

### Покажи выбор в переписке

```
## Предлагаю собрать вот на чём

| Что | Чем делаем | Почему | Сейчас | При росте |
|-----|-----------|--------|--------|-----------|
| Основа | ... | ... | бесплатно | ... с 1000 польз. |
| Данные | ... | ... | бесплатно | ... |
| Вход | ... | ... | бесплатно | ... |
| Размещение | ... | ... | бесплатно | ... |

**Итого сейчас: 0 ₸ в месяц.** Платить начнёте примерно с [событие].

Собираем на этом?
```

Итоговая сумма — то, что человек запомнит. Она обязательна.

Дождись подтверждения, прежде чем что-либо ставить.

## Сборка

### План

```
- [ ] Часть 1. Каркас — проект запускается, видна пустая страница
- [ ] Часть 2. Основа — данные, вход, общие правила
- [ ] Часть 3. Главный экран и главное действие ← рабочая версия
- [ ] Часть 4. Остальные экраны
- [ ] Часть 5. Полировка — тексты, скорость, мелочи
```

Покажи этот план человеку и отмечай в переписке, что сделано:

```
Часть 1 ✅ · Часть 2 ✅ · Часть 3 ◀ сейчас · Часть 4 · Часть 5
```

**Часть 3 ключевая.** После неё продукт уже можно показать: главный экран работает,
главное действие выполняется. Скажи это прямо — человек должен понимать, где точка
«уже не стыдно показать».

### После каждой части

1. Проверь, что проект запускается без ошибок.
2. Покажи **наблюдаемо**, а не словами:

   ```
   Часть 3 готова. Посмотрите:

   1. Выполните: npm run dev
   2. Откройте: http://localhost:3000
   3. Нажмите «Записаться» → должна появиться форма
   4. Заполните и отправьте → должно появиться «Заявка принята»

   Работает?
   ```

3. **Остановись.** Не начинай следующую часть, пока человек не сказал «дальше».

### Если что-то упёрлось

Ошибка в плане, нужна незапланированная технология, требуется решение человека —
не выдумывай обход. Остановись, объясни простыми словами, что не сходится, и предложи
два варианта выхода.

### Секреты

Ключи, пароли и токены никогда не пишутся в код — только переменные окружения, и файл
с ними сразу добавляется в `.gitignore`. Сделай это в первой же части, а не потом.

## Результат

Запиши `ARCHITECTURE.md`: ответы на шесть вопросов, таблица технологий с ценой,
структура папок, план сборки с отметками, что решили не делать в первой версии.

Человека читать файл не отправляй. Покажи в переписке:

```
## 🏗 Первая версия готова

**Запустить**: [точная команда]
**Открыть**: [адрес]
**Стоимость**: 0 ₸ в месяц
**Собрано на**: [стек одной строкой]

Отложили на потом: [список]

Идём к шагу 3 — проверим, можно ли показывать это живым людям?
```

## Чего не делать

- Не начинать сборку до утверждения технологий.
- Не собирать больше одной части за раз.
- Не предлагать платное, пока бесплатное справляется.
- Не тащить технологию, которая не нужна ни одному экрану из `DESIGN.md`.
- Не писать ключи в код.
- Не говорить «готово», не показав, что запустить и нажать.
- Не отправлять человека читать файл вместо показа в переписке.
