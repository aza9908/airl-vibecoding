# Шаг 2 — Архитектура: на чём собрать и сборка первой версии

## 📚 Покажи это человеку перед первым вопросом

```
🏗 Шаг 2 из 3 — Архитектура

Дизайн сказал, что строим и как это выглядит. Собираем всё на Firebase —
сайт, база данных и вход по логину в одном месте. Сейчас решим, какие части
Firebase нужны и сколько это будет стоить в месяц, а потом соберём первую
рабочую версию.

Сначала 6 вопросов. Потом покажу, из чего соберём и сколько стоит — вы утвердите.
Потом начнём собирать по частям: после каждой части остановимся, и вы своими
глазами посмотрите, что получилось.

Так ошибка находится через двадцать минут, а не через четыре часа, когда уже
непонятно, где она появилась.
```

## Перед стартом

Прочитай `DESIGN.md`. Его нет — скажи, что сначала нужен шаг `/airl-design`, и предложи
запустить. Человек настаивает — задай вопросы про продукт сам, но предупреди: без карты
экранов результат будет приблизительным.

## Главное правило

**Только Firebase.** Все части продукта собираются на сервисах Firebase. Не предлагай
Supabase, Vercel, Netlify, свой сервер, PostgreSQL, MongoDB и другие платформы — даже
как вариант «на выбор». Если какую-то задачу Firebase не закрывает (например, приём
платежей), подключай внешний сервис через Cloud Functions и скажи об этом прямо.

**Ничего не решай молча.** Включил сервис Firebase — объясни одной фразой, зачем он
и сколько стоит. Не знаешь ответа — спроси.

## Режим существующего проекта

Код уже есть — сначала определи по файлам, на чём он собран, и покажи:

```
Разобрался, на чём собран проект:

**Основа**: [что нашёл]
**Данные**: [где хранятся]
**Вход по логину**: [есть или нет]
**Размещение**: [где живёт]

Что делаем?
A) Добавить новую возможность — расскажите какую
B) Починить то, что работает неправильно
C) Перенести на Firebase то, что пока живёт в другом месте
D) Свой вариант
```

- **Проект уже на Firebase** — достраивай на нём, переписывать незачем.
- **Проект на другом стеке** — скажи прямо, что этот шаг работает только с Firebase,
  и предложи перенос по частям: сначала размещение (Hosting), потом вход
  (Authentication), потом данные (Firestore). Другие платформы не предлагай.

Не спрашивай заново то, что видно из кода. Скажи об этом прямо: «Вижу, что Firestore
уже подключён, вопрос про хранение пропускаю».

## Как задавать вопросы

Один вопрос за сообщение, 3–4 варианта, один помечен рекомендуемым, одна строка почему:

```
**Вопрос 3 из 6 · Где будут храниться данные?**

A) Firestore — база Firebase, бесплатно в пределах лимитов — рекомендую
B) Только файлы и картинки — Cloud Storage
C) Хранить ничего не нужно
D) Свой вариант

Рекомендую A: для первой версии бесплатного лимита хватает с запасом,
настраивается за час, платить начнёте только при реальном росте.
```

Ответ «не знаю» — бери рекомендацию, скажи об этом и иди дальше.

## Шесть вопросов

**1. Сколько человек будет пользоваться в первые полгода?**
До ста · до тысячи · больше тысячи. Определяет почти всё остальное, поэтому первый.
Подталкивай к честной оценке: завышенная цифра делает продукт дороже без пользы.

**2. Какие данные храним?**
Ничего · обычные (имена, заявки, тексты) · файлы и фото · персональные и платёжные.
Обычные данные — Firestore. Файлы и фото — Cloud Storage: для него нужен тариф Blaze,
скажи это сразу. Персональные и платёжные данные меняют требования к безопасности:
строгие правила Firestore Security Rules с первой части, номера карт в Firestore
не хранятся никогда.

**3. Нужен ли вход по логину?**
Не нужен · для сотрудников · для клиентов · для тех и других. Вход делается через
Firebase Authentication: по почте и паролю, через Google или по номеру телефона.
Вход по SMS платный уже с первых сообщений — предупреди об этом.

**4. Нужна ли оплата внутри продукта?**
Не нужна · нужна, но позже · нужна сразу. «Позже» — хороший ответ: оплата удваивает
срок первой версии, и это стоит сказать вслух. Своих платежей у Firebase нет: платёжный
сервис подключается через Cloud Functions, а для них нужен тариф Blaze.

**5. Сколько готовы платить в месяц?**
Ноль · до 20 000 ₸ · до 100 000 ₸ · без потолка. Скажи честно: у большинства первых
версий всё помещается в бесплатный тариф Spark. Тариф Blaze — оплата по факту
использования, бесплатные лимиты на нём сохраняются; при переходе на Blaze сразу
ставь лимит бюджета с уведомлением в Google Cloud.

**6. Что уже есть и оплачено?**
Ничего · аккаунт Google · проект Firebase · свой домен. Уже созданный проект Firebase
используй, а не заводи новый. Свой домен подключается к Firebase Hosting бесплатно.

## Выбор технологий

### Из чего собираем

Только сервисы Firebase. Бери столько, сколько нужно экранам из `DESIGN.md`, не больше:

| Задача | Сервис Firebase | Тариф |
|--------|-----------------|-------|
| Размещение сайта | Firebase Hosting (для Next.js с сервером — App Hosting, нужен Blaze) | Spark |
| Данные | Cloud Firestore | Spark |
| Вход по логину | Firebase Authentication | Spark (SMS — платно) |
| Файлы и фото | Cloud Storage for Firebase | Blaze |
| Серверная логика, оплата, письма | Cloud Functions for Firebase | Blaze |
| Защита от ботов | App Check | Spark |
| Аналитика | Google Analytics for Firebase | Spark |

### Лестница

Снизу вверх, без перепрыгивания:

1. то, что **уже есть** — существующий проект Firebase;
2. **тариф Spark** — бесплатно, без ограничения по сроку;
3. **тариф Blaze в пределах бесплатных лимитов** — карта привязана, но платить 0 ₸;
4. **Blaze сверх лимитов** — только когда первые три не закрывают задачу.

При бюджете «ноль» старайся уложиться в Spark: без Storage и Functions. Если они всё же
нужны — объясни, что Blaze требует привязать карту, но в пределах лимитов списаний не
будет, и поставь лимит бюджета.

### Покажи выбор в переписке

```
## Предлагаю собрать на Firebase

| Что | Сервис Firebase | Почему | Сейчас | При росте |
|-----|-----------------|--------|--------|-----------|
| Основа | [фреймворк] + Firebase SDK | ... | бесплатно | — |
| Данные | Cloud Firestore | ... | бесплатно | ... сверх 50 000 чтений в день |
| Вход | Firebase Authentication | ... | бесплатно | ... |
| Размещение | Firebase Hosting | ... | бесплатно | ... сверх 10 ГБ трафика в месяц |

**Тариф: Spark (бесплатный). Итого сейчас: 0 ₸ в месяц.** Платить начнёте примерно
с [событие].

Собираем на этом?
```

Итоговая сумма — то, что человек запомнит. Она обязательна.

Дождись подтверждения, прежде чем что-либо ставить.

## Сборка

### План

```
- [ ] Часть 1. Каркас — проект Firebase создан и подключён, страница открывается
- [ ] Часть 2. Основа — Firestore, Authentication, правила безопасности
- [ ] Часть 3. Главный экран и главное действие ← рабочая версия
- [ ] Часть 4. Остальные экраны
- [ ] Часть 5. Полировка — тексты, скорость, мелочи
```

Покажи этот план человеку и отмечай в переписке, что сделано:

```
Часть 1 ✅ · Часть 2 ✅ · Часть 3 ◀ сейчас · Часть 4 · Часть 5
```

**Часть 3 ключевая.** После неё продукт уже можно показать: главный экран работает,
главное действие выполняется. Скажи это прямо — человек должен понимать, где точка
«уже не стыдно показать».

### После каждой части

1. Проверь, что проект запускается без ошибок.
2. Покажи **наблюдаемо**, а не словами:

   ```
   Часть 3 готова. Посмотрите:

   1. Выполните: npm run dev
   2. Откройте: http://localhost:3000
   3. Нажмите «Записаться» → должна появиться форма
   4. Заполните и отправьте → должно появиться «Заявка принята»

   Работает?
   ```

3. **Остановись.** Не начинай следующую часть, пока человек не сказал «дальше».

### Если что-то упёрлось

Ошибка в плане, нужна незапланированная технология, требуется решение человека —
не выдумывай обход. Остановись, объясни простыми словами, что не сходится, и предложи
два варианта выхода.

### Секреты

Настройки веб-приложения Firebase (`apiKey`, `projectId` и т. п.) — не секрет, их можно
держать в коде клиента; защищают данные правила Firestore и Storage, а не скрытый ключ.
Поэтому правила пишутся в первой же части, а не потом: никаких `allow read, write: if true`.

Настоящие секреты — ключ сервисного аккаунта, ключи платёжных и почтовых сервисов —
никогда не пишутся в код. Для Cloud Functions — Secret Manager (`firebase functions:secrets:set`),
локально — файл окружения, сразу добавленный в `.gitignore`.

Для разработки используй Firebase Local Emulator Suite, чтобы не тратить лимиты и не
трогать живые данные.

структура папок, план сборки с отметками, что решили не делать в первой версии.


## Чего не делать

- Не предлагать ничего, кроме Firebase: ни других баз, ни других хостингов.
- Не начинать сборку до утверждения технологий.
- Не собирать больше одной части за раз.
- Не переводить на Blaze, пока хватает Spark; переводя — ставить лимит бюджета.
- Не оставлять открытые правила Firestore и Storage.
- Не тащить технологию, которая не нужна ни одному экрану из `DESIGN.md`.
- Не писать ключи в код.
- Не говорить «готово», не показав, что запустить и нажать.
- Не отправлять человека читать файл вместо показа в переписке.
