# Шаг 2 — Сборка на Firebase (версия интенсива)

## Зачем эта версия

Это сокращённый навык для воскресного интенсива. Задача одна: **каждый участник за
одно занятие получает работающий продукт по ссылке `….web.app` со входом через
Google и сохранением данных.** Предсказуемость важнее гибкости.

Поэтому:

- **Стек не выбирается.** Не предлагай альтернатив, не спрашивай про бюджет, не
  сравнивай площадки. Человек просит другое — ответь одной фразой (см. «Если просят
  то, чего здесь нет») и продолжай по плану.
- **Шаги идут строго по порядку.** Ничего не пропускай, даже если кажется, что
  человек справится сам.
- **Публикуем в первой же части.** Пустая страница на `web.app` в начале — это
  проверка, что вход в Firebase, проект и доступы работают. Ошибки доступа в начале
  чинятся за минуту, в конце — съедают полчаса.

## 📚 Покажи это человеку перед первым вопросом

```

Дизайн готов. Теперь соберём рабочую версию и сразу выложим её в интернет.

Собираем на Firebase — это сервис Google. В нём сразу есть всё, что нужно:
сайт по ссылке, хранение данных и вход через Google-аккаунт. Бесплатно,
карта не нужна.

Как пойдём:
  1. Три коротких вопроса про данные
  2. Вы создаёте проект в Firebase — я подскажу каждую галочку
  3. Я собираю продукт по частям, после каждой вы проверяете сами

Первая ссылка в интернете появится уже минут через 20.
```

## Стек — зафиксирован

| Что | Чем | Сколько стоит |
|---|---|---|
| Сайт | React + Vite | бесплатно |
| Данные | Cloud Firestore | бесплатно до 50 000 чтений в день |
| Вход | Firebase Authentication, только Google | бесплатно |
| Размещение | Firebase Hosting, адрес `ID-проекта.web.app` | бесплатно |
| Командная строка Firebase | `firebase-tools` внутри проекта | бесплатно |

**Тариф Spark, без карты.** На нём при превышении лимита Firebase просто перестаёт
отвечать до следующих суток — счёт прийти не может. Скажи это человеку вслух, это
снимает тревогу.

**Чего в этой версии нет, и предлагать это нельзя:**

- **Cloud Storage (загрузка файлов и фото)** — с конца 2024 года новые хранилища
  требуют тариф Blaze с картой. Нужна картинка — ссылка на картинку текстом или
  файл в папке `public/` проекта.
- **Cloud Functions, серверная часть** — тоже требует карту.
- **Оплата внутри продукта.**
- **Свой домен** — только адрес `….web.app`.
- **Вход по почте и паролю, по телефону** — только Google. Один способ входа —
  одна точка, где может сломаться.
- **`signInWithRedirect`** — только `signInWithPopup`. Перенаправление ломается в
  современных браузерах, когда сайт живёт на `web.app`, а вход идёт через
  `firebaseapp.com`.
- **`firebase init`** — он интерактивный и задаёт вопросы, на которые новичок
  ответит неправильно. Файлы настройки пишешь сам.
- **Глобальная установка `npm install -g`** — на Mac падает с ошибкой прав. Всё
  ставится внутрь проекта и запускается через `npx`.

## Три вопроса

Один вопрос за сообщение, варианты буквами, один помечен рекомендуемым. Ответ
«не знаю» — бери рекомендацию и иди дальше.

**1. Что храним.** Не спрашивай с чистого листа — собери из `DESIGN.md` список
того, что сохраняется, и попроси подтвердить:

```
**Вопрос 1 из 3 · Что будем хранить?**

По дизайну выходит так:

| Что | Какие поля |
|---|---|
| Заявка | имя, телефон, услуга, дата и время |

A) Всё верно — рекомендую
B) Нужно добавить или убрать поле — напишите какое
```

Держи модель данных маленькой: одна-две коллекции. Больше трёх — предложи отложить.

**2. Кто видит чужие данные.** Это определяет правила доступа к базе:

```
**Вопрос 2 из 3 · Кто что видит?**

A) Каждый видит только своё — рекомендую
B) Все вошедшие видят общий список, править может только автор
C) Клиенты видят только своё, а вы (владелец) — всё

Рекомендую A: самый простой и самый безопасный вариант.
```

**3. Почта владельца** — только если в вопросе 2 выбран C:

```
**Вопрос 3 из 3 · С какой Google-почты вы будете заходить как владелец?**

Эта почта получит доступ ко всем данным. Остальные увидят только своё.
```

При A или B вопрос 3 пропусти и скажи почему.

Затем покажи итог одним блоком и **дождись «да»**:

### Часть 2. Каркас и первая публикация

**2.1. Каркас.** Создай проект в текущей папке:

```bash
npm create vite@latest vite-tmp -- --template react --no-interactive --no-immediate
cp -R vite-tmp/. .
rm -rf vite-tmp
npm install
npm install firebase
npm install --save-dev firebase-tools
```

Именно так, через временную папку. Не создавай проект прямо в `.`: в непустой
папке Vite без терминала молча отменяется, а с `--overwrite` **стирает
`DESIGN.md`**.

**2.2. Секреты и игнор.** Сразу, до любого коммита, допиши в `.gitignore`
(`.env.local` Vite уже закрывает строкой `*.local` — проверь, что она есть):

```
.firebase/
firebase-debug.log
```

**2.3. Файлы Firebase.** Не запускай `firebase init`. Создай руками.

`.firebaserc`:

```json
{ "projects": { "default": "ID-ПРОЕКТА" } }
```

`firebase.json`:

```json
{
  "hosting": {
    "public": "dist",
    "ignore": ["firebase.json", "**/.*", "**/node_modules/**"],
    "rewrites": [{ "source": "**", "destination": "/index.html" }]
  },
  "firestore": { "rules": "firestore.rules" }
}
```

`firestore.rules` — пока всё закрыто, откроем в части 4:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if false;
    }
  }
}
```

В `package.json` добавь в `scripts`:

```json
"deploy": "vite build && firebase deploy --only hosting,firestore:rules"
```

**2.4. Вход в Firebase из терминала — делает человек.** Команда интерактивная, она
открывает браузер. Ты её запустить за человека не можешь. Скажи:

```
Сейчас нужно один раз связать этот компьютер с вашим Google-аккаунтом.

1. Откройте терминал внизу VS Code (Terminal → New Terminal)
2. Вставьте и нажмите Enter:

   npx firebase login

3. Спросит про сбор статистики — ответьте n и Enter
4. Откроется браузер — войдите в ТОТ ЖЕ Google-аккаунт, в котором создавали проект
5. Нажмите «Разрешить»
6. В терминале появится «Success! Logged in as …» — напишите мне «готово»
```

Затем проверь сам:

```bash
npx firebase projects:list
```

Нужного ID в списке нет — человек вошёл не тем аккаунтом. Это самая частая
поломка, разбор — в `references/troubleshooting.md`.

**2.5. Настройки сайта.** Получи их командой, а не просьбой скопировать из консоли —
так не будет опечаток:

```bash
npx firebase apps:sdkconfig WEB
```

Приложений несколько — команда попросит выбрать; возьми то, что человек
регистрировал в части 1. Приложения нет — вернись к блоку «Регистрируем сайт» в
`references/firebase-console.md`.

Запиши значения в `.env.local` (значения в переписку не печатай):

```
VITE_FIREBASE_API_KEY=…
VITE_FIREBASE_AUTH_DOMAIN=ID-ПРОЕКТА.firebaseapp.com
VITE_FIREBASE_PROJECT_ID=…
VITE_FIREBASE_STORAGE_BUCKET=…
VITE_FIREBASE_MESSAGING_SENDER_ID=…
VITE_FIREBASE_APP_ID=…
```

`authDomain` оставь как выдал Firebase — `firebaseapp.com`. Не меняй на `web.app`:
это потребует отдельной настройки в Google Cloud.

Создай `src/firebase.js`:

```js
import { initializeApp } from "firebase/app";
import { getAuth, GoogleAuthProvider } from "firebase/auth";
import { getFirestore } from "firebase/firestore";

const app = initializeApp({
  apiKey: import.meta.env.VITE_FIREBASE_API_KEY,
  authDomain: import.meta.env.VITE_FIREBASE_AUTH_DOMAIN,
  projectId: import.meta.env.VITE_FIREBASE_PROJECT_ID,
  storageBucket: import.meta.env.VITE_FIREBASE_STORAGE_BUCKET,
  messagingSenderId: import.meta.env.VITE_FIREBASE_MESSAGING_SENDER_ID,
  appId: import.meta.env.VITE_FIREBASE_APP_ID,
});

export const auth = getAuth(app);
export const googleProvider = new GoogleAuthProvider();
export const db = getFirestore(app);
```

Скажи человеку одной фразой: ключ Firebase для сайта не секретный, его и так видит
каждый браузер, но в `.env.local` он не попадёт на GitHub, и Google не будет слать
тревожные письма «ваш ключ опубликован».

**2.6. Первая публикация.** На главной — название продукта из `DESIGN.md` и одна
строка. Затем:

```bash
npm run deploy
```

В конце вывода будет `Hosting URL: https://ID-ПРОЕКТА.web.app`. Открой адрес сам
(`curl -sI` или браузер) и убедись, что отдаётся страница, а не ошибка.

Покажи человеку:

```
Часть 2 готова — продукт уже в интернете 🎉

Откройте: https://ID-ПРОЕКТА.web.app

Должно быть: название «…» на странице. Открывается с телефона тоже.
Пока это пустая заготовка — дальше наполним.

Работает?
```

### Часть 3. Вход через Google

Сделай экран входа из `DESIGN.md` с одной кнопкой «Войти через Google».

Правила:

- Только `signInWithPopup(auth, googleProvider)`. Никакого `signInWithRedirect`.
- Состояние входа — через `onAuthStateChanged`, пока оно не пришло, показывай
  загрузку, а не экран входа (иначе экран входа мелькает при каждом обновлении).
- Кнопка «Выйти» — `signOut(auth)`.
- Ошибки входа переводи на русский. Минимум:

  | Код | Что показать человеку |
  |---|---|
  | `auth/popup-closed-by-user` | ничего не показывай — человек сам закрыл окно |
  | `auth/popup-blocked` | «Браузер заблокировал окно входа. Разрешите всплывающие окна для этого сайта» |
  | `auth/unauthorized-domain` | «Этот адрес не разрешён для входа» — и смотри troubleshooting |
  | `auth/operation-not-allowed` | «Вход через Google не включён в Firebase» — и смотри troubleshooting |
  | любая другая | «Не получилось войти. Попробуйте ещё раз» + код в консоль браузера |

Проверка в две точки — **обе обязательны**:

```
Часть 3 готова. Проверьте в двух местах.

На компьютере:
1. В терминале: npm run dev
2. Откройте http://localhost:5173   ← именно localhost, не 127.0.0.1
3. «Войти через Google» → выберите аккаунт → должно появиться ваше имя

В интернете (я уже опубликовал):
4. Откройте https://ID-ПРОЕКТА.web.app
5. То же самое — вход должен сработать и там

Получилось в обоих местах?
```

Перед этим опубликуй: `npm run deploy`.

Что-то не так — сначала `references/troubleshooting.md`, раздел «Вход через
Google». Почти все поломки этой части — галочка в консоли, а не код.

### Часть 4. Главный экран и главное действие

Собери главный экран и главное действие из `DESIGN.md`. Данные — в Firestore.

**Модель данных** — по ответу на вопрос 2:

- **A, каждый видит своё:** `users/{uid}/ИМЯ_КОЛЛЕКЦИИ/{id}`.
- **B, общий список:** `ИМЯ_КОЛЛЕКЦИИ/{id}` с полем `ownerId` = `auth.currentUser.uid`.
- **C, владелец видит всё:** `ИМЯ_КОЛЛЕКЦИИ/{id}` с полем `ownerId`; клиент читает
  через `where("ownerId", "==", uid)`, владелец — без фильтра.

В каждом документе — `createdAt: serverTimestamp()`.

**Правила доступа** — возьми готовый шаблон из
`references/firestore-rules.md` под выбранный вариант, подставь имена коллекций,
перечисли разрешённые поля. Шаблон не упрощай и не заменяй на `if true` «чтобы
заработало» — это открытая дверь для всего интернета.

Опубликуй и сайт, и правила одной командой: `npm run deploy`.

Главное действие должно показывать три состояния из `DESIGN.md`: пусто, загрузка,
ошибка — дословно теми текстами.

Проверка:

```
Часть 4 готова — это уже рабочая версия, её не стыдно показать.

1. Откройте https://ID-ПРОЕКТА.web.app и войдите
2. [главное действие: «Нажмите "Записаться", заполните, отправьте»]
3. Должно появиться «[текст успеха из DESIGN.md]»
4. Обновите страницу — запись должна остаться на месте
5. Откройте сайт в окне инкогнито, войдите ДРУГИМ Google-аккаунтом —
   [чужой записи видно не должно / должна быть видна в общем списке]

Всё так?
```

Пункт 5 — это проверка правил доступа руками. Не пропускай.

«Missing or insufficient permissions» в консоли браузера — правила не совпадают с
путями в коде, см. troubleshooting.

## Чего не делать

- Не предлагать другой стек, площадку или домен.
- Не включать Cloud Storage, Cloud Functions и не просить привязать карту.
- Не запускать `firebase init` и не ставить пакеты глобально.
- Не использовать `signInWithRedirect`.
- Не писать правила `allow read, write: if true` даже «на время».
- Не собирать больше одной части за раз и не идти дальше без «дальше».
- Не выдумывать ID проекта и не печатать значения ключей в переписку.
- Не говорить «готово», пока сам не открыл адрес `web.app`.
