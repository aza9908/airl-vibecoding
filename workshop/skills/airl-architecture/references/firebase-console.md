# Консоль Firebase — точный список галочек

Веди человека **по одному блоку за сообщение**. После каждого блока — «сделали?».
Текст блоков можно показывать человеку как есть.

Консоль Firebase иногда переименовывает кнопки и предлагает лишнее (Gemini, Firebase
Studio, «Google Developer Program», пробный период). Правило для человека одно:
**всё, что не написано в шаге, — пропускаем или закрываем крестиком.**

---

## Блок 1. Аккаунт и новый проект

```
1. Откройте console.firebase.google.com

2. Войдите ЛИЧНЫМ Google-аккаунтом (@gmail.com).
   Рабочая почта компании часто запрещает создавать проекты — тогда
   на последнем шаге будет ошибка без объяснений.
   Запомните, в какой аккаунт вошли: этот же понадобится в терминале.

3. «Создать проект» (Create a project / Get started with a Firebase project)

4. Название — любое, например название вашего продукта.
   Под названием мелким шрифтом виден ID проекта — запишите его.

5. Поставьте галочку согласия с условиями, если спросит → «Продолжить»

6. Gemini в Firebase / AI-помощник — выключите или пропустите
7. Google Analytics — ВЫКЛЮЧИТЕ переключатель. Он не нужен и добавляет
   лишний шаг с выбором аккаунта.

8. «Создать проект» → подождите полминуты → «Продолжить»
```

Если выскакивает «превышен лимит проектов» — у аккаунта уже много старых проектов.
Пусть удалит ненужный или возьмёт другой личный аккаунт.

## Блок 2. Регистрируем сайт

```
1. На главной странице проекта нажмите значок </>  (Web).
   Если его не видно — шестерёнка слева вверху → Project settings →
   внизу «Your apps» → значок </>

2. App nickname — любое, например «сайт»

3. Галочку «Also set up Firebase Hosting» — НЕ ставьте.
   Хостинг я настрою сам из проекта.

4. «Register app»

5. Появится кусок кода с firebaseConfig — копировать НЕ нужно,
   я заберу настройки сам. Нажмите «Continue to console».
```

---

## Блок 3. Включаем вход через Google — здесь чаще всего застревают

```
1. Слева меню: Build (Создание) → Authentication

2. Кнопка «Get started» (Начать) — обязательно нажмите.
   Без неё вход не работает вообще, даже если дальше всё сделать правильно.

3. Вкладка «Sign-in method» (Способ входа)

4. В списке провайдеров выберите «Google»

5. Переключатель «Enable» (Включить) — включите

6. «Project support email» (Почта поддержки) — выберите свою почту
   из выпадающего списка. ЭТО ОБЯЗАТЕЛЬНОЕ ПОЛЕ: без него кнопка
   «Save» не нажимается или выдаёт ошибку.

7. «Public-facing name» — название, которое люди увидят в окне входа
   Google («Войти в …»). Можно оставить как есть или написать
   название продукта.

8. «Save» (Сохранить)

9. Проверка: в списке у Google должно стоять «Enabled» (Включено)
   с зелёной галочкой.
```

Затем проверка разрешённых адресов:

```
10. В том же разделе Authentication — вкладка «Settings» (Настройки)
11. Слева «Authorized domains» (Авторизованные домены)
12. В списке должны быть три адреса:
      localhost
      ID-ПРОЕКТА.firebaseapp.com
      ID-ПРОЕКТА.web.app
    Обычно они добавляются сами. Какого-то нет — «Add domain» и впишите.
```

Ничего больше в Authentication не трогать: Google Cloud Console, OAuth consent
screen, Client ID — для входа через Firebase это **не нужно**, Firebase настраивает
их сам. Если человек нашёл инструкцию в интернете, где надо идти в Google Cloud, —
это другой сценарий, скажи не ходить.

## Блок 4. Создаём базу Firestore

```
1. Слева меню: Build → Firestore Database

2. «Create database» (Создать базу данных)

3. Если спросит редакцию (Edition) — выберите «Standard»

4. Database ID — оставьте «(default)», не меняйте

5. Location (Расположение) — выберите «eur3 (europe)» или любой
   европейский регион. ВАЖНО: поменять потом нельзя, только создавать
   базу заново.

6. Режим правил — «Start in production mode» (Рабочий режим).
   НЕ выбирайте «test mode»: он открывает базу всему интернету на 30 дней,
   а потом закрывает целиком, и продукт ломается.
   Правила доступа я напишу сам.

7. «Create» → подождите минуту, пока база создаётся
```

---

## Блок 5. Забираем ID проекта

```
1. Шестерёнка слева вверху → «Project settings» (Настройки проекта)
2. Строка «Project ID» — скопируйте её и пришлите мне.

Это не название проекта! Название может быть «Барбершоп»,
а ID — «barbershop-4f2a1». Нужен именно ID.
```

## Что НЕ нажимать

- **Upgrade / Blaze / привязать карту** — не нужно, всё работает на бесплатном Spark.
- **Storage** — требует карту, в этой версии не используем.
- **Functions** — требует карту, не используем.
- **Realtime Database** — это другая база, нам нужна Firestore.
- **App Check, Extensions, Firebase Studio, Genkit** — не нужны сегодня.
