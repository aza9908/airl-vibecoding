# Шаг 3 — Безопасность (версия интенсива)

## 📚 Покажи это человеку первым

```
🔒 Шаг 3 из 3 — Безопасность

Продукт работает и уже в интернете. Проверим, можно ли давать ссылку людям.

В небольших продуктах утечки почти всегда случаются по трём причинам:
ключ случайно попал в общий доступ, база открыта всем, или один
пользователь видит данные другого. Это и проверю — займёт 5–10 минут.

В конце скажу прямо: можно или нельзя.
```

## Жёсткие правила

- **Значения ключей не печатаются никогда** — только имя переменной и файл.
- Ничего не публикуется без явного «да».
- Не выдумывай находки, чтобы отчёт выглядел солиднее. Чисто — так и скажи.

## Проверка — шесть пунктов

Проверяй сам, человеку покажи только результат.

**1. Ключи не уедут на GitHub.**
`.env.local` есть в `.gitignore`. Если проект уже под git — `git ls-files` не
показывает `.env.local`, а `git log --all -p -S "AIza"` пуст. В коде (`src/`) нет
строк `AIza…` — ключ берётся только из `import.meta.env`.

**2. Нет серверных ключей.**
В проекте нет `serviceAccount*.json`, `*-firebase-adminsdk-*.json`, приватных ключей.
Им не место в сайте никогда.

**3. База не открыта всем.**
В `firestore.rules` нет `if true`, нет `request.time <` (тестовый режим), нет
`if request.auth != null` на всю базу (`/{document=**}`). Правила совпадают с
шаблоном из `../airl-architecture/references/firestore-rules.md` (соседний навык) под выбранный вариант.

**4. Правила реально опубликованы.**
Выполни `npm run deploy` ещё раз или попроси человека открыть консоль Firebase →
Firestore Database → вкладка Rules и сверить, что там тот же текст, что в
`firestore.rules`.

**5. Чужие данные не видны — проверка руками.**
Если в части 4 сборки проверка вторым аккаунтом не проводилась — проведи сейчас:

```
Последняя проверка руками, 2 минуты:

1. Откройте https://ID-ПРОЕКТА.web.app в окне инкогнито
   (Ctrl+Shift+N, на Mac Cmd+Shift+N)
2. Войдите ДРУГИМ Google-аккаунтом
3. [Записи из основного аккаунта видно не должно / в общем списке видно,
   но кнопок «изменить» и «удалить» нет]

Как у вас?
```

**6. Счёт прийти не может.**
Проект на тарифе Spark (в консоли Firebase внизу слева написано «Spark»). Нет
Cloud Functions и Storage. Если человек всё-таки перешёл на Blaze — 🔴, это
выходит за рамки интенсива; попроси вернуть Spark или поставить бюджет:
Firebase Console → шестерёнка → Usage and billing → Details & settings.

## Что чинишь сам

Покажи список правок, получи «да», затем правь и публикуй: дописать `.gitignore`,
вынести ключ из кода в `.env.local`, исправить правила под шаблон.

Ключ уже попал в историю git и репозиторий публичный — скажи прямо: удаления
строки мало. Для ключа Firebase для сайта это не катастрофа (он публичный по
задумке), но Google будет слать предупреждения. Полный разбор утёкших ключей и
ограничение ключа по адресу сайта — в полном наборе навыков AIRL.

## Результат — покажи в переписке

Запиши `SECURITY.md`, читать человека не отправляй. Покажи:

```
## 🔒 Проверка закончена

**Можно давать ссылку людям: ДА**

| Что проверили | Результат |
|---|---|
| Ключи не попадут на GitHub | ✅ |
| Серверных ключей в проекте нет | ✅ |
| База закрыта для чужих | ✅ |
| Правила опубликованы | ✅ |
| Чужой аккаунт не видит ваши данные | ✅ |
| Неожиданный счёт невозможен — тариф Spark | ✅ |

**Что я исправил**: [список или «ничего, всё было чисто»]
```

🔴 хотя бы в одной строке — ответ «НЕТ, пока нельзя», что мешает и что делать.

## Чего эта проверка не покрывает

Скажи одной строкой в конце: «Это быстрая проверка под сегодняшний продукт. Полная
проверка безопасности AIRL смотрит ещё ввод данных, платные сервисы, потолки
расходов и боевую среду.»

Затем, если запущен из `/airl-start`, верни ему управление.

## Чего не делать

- Не печатать значения ключей.
- Не открывать правила «чтобы заработало».
- Не публиковать без согласия.
- Не пугать: объяснять простыми словами, что может случиться.
